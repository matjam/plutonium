Date: 2026-10-31. Base: `origin/main` at `d3d7076c`. Docs and status only; no compiler code was changed.

Method. For each dependency I read its roadmap entry, ran `git show --stat` on the commit it cites, and
checked that the test cases the commit added (or their successors) are still in the tree. I did not build the
compiler or run the compiler tests. So "tests present" means the cases exist in `tests/` or `testdata/` and
their expected output shows the behavior. It does not mean I ran them. Many cited commits are from the Go
implementation, and their Go unit tests went with it; I name the corpus cases that now carry the same checks.

### Item 85: what works and what is tuning

Works, and verified natively on 2026-10-12 and 2026-10-14 (the records above):

- The shared generation directory covers every checked pointer, small and large contiguous Slab and Chunked blocks, nested backing and inferred custom allocators.
- Address histories and saved incarnations stop a stale view matching reused memory, and keep partial-release views valid.
- D7: `arena.NewFixed(capacity, parent) Fixed` owns private backing, `arena.NewUnsafe(buf)` is the manual route, and the ordinary safe API has no unchecked exemption and no hosted epoch wrap.
- Marks, `Reset`, `Release` and drop invalidate exactly what they reclaim (E3313 for local arenas).

Tuning only (speed, no change in what is accepted or rejected): coherent whole-range and ancestor snapshots,
same-granule scalar checks, proven extent reuse, interval lookup hints without cached liveness. The recorded
costs are dense reads 16.498 ns against 0.809 ns before, and a consumed 1024-byte copy and clear 1503.776 ns
against 49.247 ns. These belong to item 85's own tuning list and to the performance plan. They do not block
item 20.

## Verdict on item 20

Item 20 cannot be marked done. Items 78, 86 to 89 and 92 are done, the speed tuning of item 85 is not a
correctness item, and every library owner named in item 51 exists. What blocks it:

1. Item 75 / G26: a consuming method used as a method value is accepted. Section 18.5 requires an error.
2. Item 101, phases 3 and 4: generation checks for early boot, interrupts and arenas in kernel builds (section 18.11).
3. The four residual view-tracking cases at the end of item 138 (section 18.3).
4. The rules below that have no test. These are missing tests, and for the first item also a missing check.

Items 1 to 3 are separate roadmap items. If the owner of the roadmap treats them as outside item 20, only the
missing tests below remain.

## Rules with no test under `tests/` or `compiler/*/testdata`

Search method. There is no `compiler/*/testdata` directory in the tree. I searched `tests/` and `testdata/` for
the codes E3001 to E3010, E3100 to E3102, E3201 to E3214, E3301 to E3314, E3501, E2406, E2454, E2455, for the
message text of each ownership diagnostic in every `brief.out` and `default.out`, and for source constructs in
`*.p` files. (`docs/diagnostics.md` does not exist; the codes are in `compiler/internal/diag/codes.p`,
`catalog_own.p` and `compiler/internal/types2/errors/plutonium.p`.) The search is partial: I checked the rules
below one by one, and I read only the headers of the run-time drop programs (`dropsites`, `dropflow`,
`dropbase`, `deferowner`, `drops`, `owniface`, `ownunion`, `ownany`). Rules I did not check are not listed.

Every ownership code E3001 to E3010 and E3100 to E3102, E3201 to E3214, E3301 to E3314 and E3501 appears in at
least one test. Four codes appear only in the `pluto explain` listings (`tests/testdata/explain`), so no test
makes the compiler report them:

- E3205, `owner` on an alias (7.18, "Only in a type definition").
- E3208, `take` of an argument that is not a pointer (13.10, 18.5).
- E3209, `unsafe.Drop` of an argument that is not a pointer (18.6).
- E3007, a `//pu:resultholds` directive that does not match the function (18.3). E3008 is tested.

Sub-forms of a tested code with no test:

- E3202 (7.18, "Never inferred"): only the plain field form is tested (`tests/diag/owners`). Not tested: an embedded owner field, a field that is an array of owners, a named array of owners (`type Pages [4]Frame`), an interface that embeds an owning interface, `type B A` where `A` is an owner, and a generic type that stores an `owner` type parameter without being declared `owner`. The compiler has code for the first five (`compiler/internal/types2/plutonium_owner.p`, `checkNotOwner`, `ownerFields`).
- E3204 (7.18, "Declared"): only a slice and an enum are tested. Not tested: string, map, channel, function, boolean, float, packed, volatile, and `owned`, `shared`, `synced`, `weak`; and `type B owner A` where `A` is `owned[T]`.
- E3210: only `owned[Reader]`; `shared` and `synced` of an interface are not tested.
- E3212 (7.19, "Creation"): only an integer constant converted to an owner outside its package. Not tested: a `*T` view converted into a box ("A `*T` view never becomes a box").

Rules with no test and no code:

- Consuming method value, `done := c.Close` (11.9, 18.5 "Methods"). Also not implemented, see above.

Rules with no test found, where I could not tell whether the check exists:

- One expression that moves a variable and uses it elsewhere, in either order: `send(buf, buf.Len())` and `send(buf.Len(), buf)` (18.5). Roadmap item 75 says it is done under E3301, but I found no test with this shape and could not find where `compiler/internal/moves` checks the second order. The argument walk in `moves/expr.p` is sequential.
- A `select` send case that moves an owner only if the case proceeds, with the owner "possibly moved" after the `select` (18.5 "Select"). `dropflow.p` has a select with a receive only.
- `aligned[T, N]` of owners as an owner without a declaration (7.18, "Implied"). `ring` of owners is tested (`ringowners.p`).
- `Drop` is never promoted from an embedded owner, and a box's `Drop` and `Clone` are never promoted from an embedded box (7.18 "Embedding", 7.19 "Own methods"). `embedshared.p` covers `shared` and `synced` only.
- A box used as a `*T`: stored in a `*T` variable, returned as `*T`, or passed where `*T` is expected is a compile error (7.19, "Use").
- A map in an ordinary interface that is returned or stored, rejected (7.9, item 88). Only the accepted package-map control exists.
- `unsafe.Drop(p)` on a real value, as a direct program test (18.6). It is used by the library (`alloc.Free`, containers), so it runs there, but no case in `tests/` or `testdata/` calls it.

Not checked, so not listed: the order of drops for parameters, `sync.Scope` parameters and results (18.6 first
bullets); counts that become atomic at the first task (18.7); strings (18.8); `alloc.Use` windows (18.9);
generation-check details (18.11); chapter 18.12 beyond `pluto vet -unsafe`; and the kind table of 8.7, which has
`tests/types2/ownershipkind`.
